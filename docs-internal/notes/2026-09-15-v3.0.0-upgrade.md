# GeoLibre v3.0.0 업그레이드 연구 노트

날짜: 2026-09-15
범위: `dev` 브랜치, `v2.9.0 → v3.0.0` (원본 95커밋, 476파일 병합)

## 1. 원본(GeoLibre)에서 3.0.0에 들어온 것

압도적으로 큰 축은 **Cesium 3D globe 대개편**이다. 지금까지 globe는 보조 뷰(그리드
패널) 수준이었는데, 이번 릴리스로 2D MapLibre 지도와 대등한 **1급 렌더러**가 됐다.

### Cesium/3D globe

- **`MapEngine` 추상화 + `CesiumEngine`.** 앱이 더 이상 "MapLibre + 어쩌다 Cesium"이
  아니라 `MapEngine` 인터페이스를 통해 두 렌더러를 대칭적으로 다룬다. UI는
  `engine.capabilities`로 기능을 켜고 끈다(렌더러 이름으로 분기하지 않음).
- **`primaryRenderer` 프로젝트 필드.** 프로젝트 자체가 "주 렌더러는 MapLibre냐
  Cesium이냐"를 저장한다. `PrimaryCesiumCanvas`가 globe를 주 화면으로 띄운다.
- 피처 피킹·팝업·하이라이트, 베이스맵/지형 피커, 툴바 컨트롤, 커서 좌표·라벨,
  레이어 필터·Time Slider 클록·스토리 투명도 연동, 마우스 커서 라벨.
- **폴리곤 돌출(extrusion) + 실제 3D 고도.** 확장형 스타일 표현식까지 지원하는
  고도화된 버전 — geoIM3D가 만들었던 구버전 돌출 코드는 이걸로 완전히 대체됐다.
- 피처별 심볼로지, 포인트 레이어 클러스터링/배치, 레이어 필터.
- **`ProtocolImageryProvider` — 프로토콜 브릿지 방식 이미저리.** COG, 래스터
  PMTiles, MBTiles, 네이티브 타일 페처를 MapLibre가 등록한 프로토콜 핸들러
  (`maplibregl.addProtocol`)를 통해 그대로 globe에서도 읽는다. **이 덕분에
  geoIM3D의 `vworld://` 커스텀 스킴도 별도 코드 없이 저절로 globe에서 동작한다**
  (아래 3절 참고).
- I3S, 포인트 클라우드, 스플랫 타일셋 네이티브 지원. 타일 기반 벡터 레이어를
  globe에 드레이프(drape). Cesium Ion 에셋을 id로 직접 로드. CZML 동적 3D 씬,
  네이티브 KML, 지형 프로파일. `Cesium3DTileStyle`로 3D Tiles 분류(classify).
- **엔진별 플러그인 분기 (#2262/#2273).** 플러그인이 `engines: ["maplibre",
  "cesium"]`을 선언하고, Plugins 메뉴가 현재 렌더러 기준으로 걸러 보여준다 —
  geoIM3D 플러그인들이 이번에 이 메커니즘을 쓰게 됐다(3절).
- Sun, Atmospheric Effects, Flight Simulator, 날씨 플러그인의 네이티브 Cesium
  분기.

### 그 외

- ArcGIS Feature Service 쓰기(write-back) 편집, ArcGIS MapServer/WMTS/이미지
  오버레이의 3D 렌더링.
- Portolan 카탈로그 브라우저, Dimensions(치수) 플러그인.
- 필드 컬렉션 다중 사진 첨부, 편집 가능한 SVG 프린트 레이아웃 export.
- 라벨 숫자 필드 천단위 구분자, 히트맵 팔레트/가중치, 벡터 버퍼 방향(안쪽/경계
  가로지름) 옵션, 래스터 클래스별 색상/투명도.
- 스크린샷 준비 상태를 쿼리 파라미터로 노출.

## 2. 병합 자체

충돌 13개 파일(대부분 "양쪽 다 추가" 유형). 상세 절차와 파일별 판단은
[`docs-internal/upstream-merge.md`](../upstream-merge.md)에 기록. 여기서는 이번에
**geoIM3D가 실제로 뭘 더 했는지**만 정리한다.

## 3. geoIM3D가 추가로 한 작업

병합 커밋 하나로 안 끝났다 — 원본이 우리 기능을 흡수/능가한 부분을 걷어내고,
남는 geoIM3D 전용 기능은 원본 구조에 맞게 다시 얹는 작업이 이어졌다.

1. **3D 돌출 코드 삭제, 원본 채택.** `packages/map/src/cesium-layer-sync.ts`의
   구버전 돌출 로직(`extrusionHeightOf`, `applyExtrusion`)을 지우고 원본의
   확장형 스타일 표현식 돌출을 그대로 받음.
2. **`setCesiumTileUrlResolver` 완전 삭제.** VWorld `vworld://` 스킴을 globe용으로
   재작성해주던 우리 훅 — 원본의 `ProtocolImageryProvider`가 MapLibre 프로토콜
   레지스트리를 직접 읽으면서 이미 필요 없어짐. 호출부(`useCredentials.ts`)와
   그것만 테스트하던 `tests/cesium-basemap-tiles.test.ts`도 함께 제거.
3. **`PrimaryGlobeSwitch.tsx` 삭제.** globe를 주 화면으로 쓰는 기능 자체를
   원본이 `primaryRenderer` + `PrimaryCesiumCanvas`로 흡수(#2217, #2260).
   3D 오브젝트 플러그인의 `PrimaryViewBridge` 인터페이스는 그대로 두고 구현만
   스토어 구독으로 교체.
4. **geoIM3D 전용 Cesium 기능 3개는 유지하되, DI로 재구성.** (사용자 피드백:
   "원본 우선으로" → "추가했던 기능은 원본에 추가하는 형태로") 타일셋 배치
   매트릭스, 타일셋 로딩 진행률, globe에서의 Layer Swipe를
   `cesium-layer-sync.ts`가 직접 import하지 않고, 원본이 이미 쓰던 DI 패턴
   (`CesiumLayerSyncDeps.onTilesetFields`)을 확장해 연결. fork 모듈 import는
   호스트 레이어(`cesium-engine.ts`)에만 남김.
5. **플러그인 엔진 선언 추가.** 3D 객체·VWorld·날씨(KMA) 플러그인이 모두
   `engines: ["maplibre", "cesium"]`을 선언하도록 수정 — 안 그러면 Plugins
   메뉴에서 전부 "2D만"으로 표시되고 Cesium이 주 화면일 때 메뉴에서 빠짐.
   - 이 과정에서 `plugin-engine-audit` 정적 검사 테스트가 실제 버그를 하나
     잡음: VWorld의 "현재 화면 건물 불러오기"가 `app.getMap()?.getBounds()`를
     썼는데, 이건 globe가 주 화면일 때 null이라 Cesium에서 조용히 아무 일도
     안 했음 → `app.getViewBounds()`(엔진 무관 API)로 교체.
6. **`TILESET_COMPANION_ENABLED` 킬스위치 복구.** 예전에 globe 탭이
   `display:none`으로 숨겨져 있던 시절 "갈 방법이 없으니 꺼둠"으로 하드코딩된
   플래그가 그대로 남아 있었음. `primaryRenderer`로 globe가 실제 도달
   가능해진 지금은 stale한 코드였고, 이 때문에 `public/objects/manifest.json`의
   번들 예시 파일(고기리 공원 등)이 Cesium에서 로드가 거부되고 있었음 — 사용자가
   보고한 "예시파일이 안 올라간다" 버그의 원인. `true`로 되돌림.

## 4. 검증

매번 `npm run build` + `npm run test:frontend` + `npm run check:rust`로 확인.
최종 상태: 8473/8475 통과. 남은 1개(`gaussian-splat-drop.test.ts`의 소스
정규식 검사)는 병합 **이전** `dev`에서도 이미 실패 중이던 무관한 기존 버그로,
임시 `git worktree`로 재현해서 확인함 — 이번 작업 범위에서 고치지 않음.

## 5. 남은 것 / 알아둘 것

- **`vite-proxy-guard.ts`가 어떤 tsc 프로젝트에도 안 걸려 있음.**
  `apps/geolibre-desktop/tsconfig.node.json`이 `vite.config.ts`만 include하는데,
  `composite: true`라 vite.config.ts가 import하는 `vite-proxy-guard.ts`와
  `vite-plugins/*.ts`가 자동으로 딸려 들어오지 않고 `include`에 명시가 필요함
  (`npx tsc -p apps/geolibre-desktop/tsconfig.node.json --noEmit`로 재현 가능,
  TS6307). 즉 SSRF 가드 로직이 `npm run build`/`ci` 어디서도 타입체크되지
  않고 있음 — 원본(upstream)부터 있던 갭이라 이번 병합과는 무관하지만, 보안
  관련 코드라 별도로 고칠 가치가 있음. **아직 손 안 댐.**
- `dev`에 로컬 커밋 5개가 쌓여 있고 아직 `push` 전.
